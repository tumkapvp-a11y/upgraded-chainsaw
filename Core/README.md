# Core (Paper 1.21.11)

Плагин-ядро сервера. Автор: **x1no4ekk**. Java 21, Maven, MySQL (HikariCP).

> Этап 1: MySQL + кэш пользователей, GUI-фреймворк на `InventoryHolder`, хомы через «Рог телепортации».
> Команды, киты, варпы и чат добавляются на следующем этапе.

## Сборка

```bash
cd Core
mvn clean package
# target/Core-1.0.0.jar
```

## Запуск

1. Положите jar в `plugins/`, запустите сервер один раз.
2. Заполните секцию `database` в `plugins/Core/settings.yml` (MySQL 5.7+/8.0 или MariaDB).
3. Перезапустите сервер. Если подключиться к MySQL не удалось — в консоли будет `SEVERE`, и плагин выключится.

Таблицы создаются автоматически: `core_users`, `core_homes`, `core_warps`, `core_enderchests`,
`core_stats`, `core_kit_cooldowns`, `core_ignores`.

## Хомы и Рог телепортации

- `/sethome <название>`, `/delhome <название>` — управление точками дома.
- `/home` отключена: телепортироваться можно **только** через Рог телепортации (`GOAT_HORN` с PDC-меткой).
- ПКМ рогом открывает меню домов, клик по дому — звук рога и `teleportAsync()`.
- Рецепт, название, описание, звук и перезарядка рога настраиваются в `settings.yml` (`teleport-horn`).
- `/playerhome <игрок> [дом]` — меню/телепорт к домам другого игрока (работает и для оффлайн-игроков).
- `/core horn [игрок] [кол-во]` — выдать рог, `/core reload` — перезагрузить `settings.yml` и `messages.yml`.

## Права

| Право | По умолчанию | Описание |
|---|---|---|
| `core.sethome`, `core.delhome` | все | создание/удаление домов |
| `core.homes.<группа>` | — | лимит домов из `homes.limits` |
| `core.homes.unlimited` | op | без лимита домов |
| `core.horn.use`, `core.horn.craft` | все | использование и крафт рога |
| `core.horn.bypass-cooldown` | op | без перезарядки рога |
| `core.playerhome` | op | `/playerhome` |
| `core.admin` | op | `/core` |

## Память и потоки

- Кэш `ConcurrentHashMap<UUID, User>` только для онлайн-игроков: загрузка в `AsyncPlayerPreLoginEvent`,
  выгрузка из RAM и асинхронное сохранение в `PlayerQuitEvent`. Отклонённые входы вычищаются задачей очистки.
- В коллекциях нет `Player`/`Entity` — только `UUID`; локации хранятся по имени мира.
- Чтения — в пуле потоков, записи — в одном потоке-писателе (порядок записей сохраняется,
  повторный вход ждёт завершения сохранения). Все JDBC-ресурсы закрываются через try-with-resources.
- Меню — `InventoryHolder` без глобальных списков и фоновых потоков: после закрытия всё собирает GC.
